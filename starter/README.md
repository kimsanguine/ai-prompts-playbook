# Starter Path

AI를 처음 배우는 사용자는 30개 프롬프트를 모두 볼 필요가 없습니다. 아래 5개만 순서대로 실행하면 “AI에게 질문하는 법”의 기본 흐름을 익힐 수 있습니다.

## 1. 경쟁사 감성 분석

**목표:** 리뷰 데이터에서 사용자 불만과 기회를 찾습니다.

**준비물:** 경쟁사 이름, 리뷰 20개 이상

**실행:** [`prompts/analyze/competitor-sentiment.md`](../prompts/analyze/competitor-sentiment.md)의 `Layer 1`부터 시작합니다.

**좋은 결과 기준:**
- 페르소나가 3개 이상으로 분리되어 있다.
- 각 페르소나에 감정 점수와 근거 리뷰가 있다.
- 기회가 “우리 제품이 할 일”로 바뀌어 있다.

## 2. 문제 정의 프레이밍

**목표:** 모호한 기회를 실행 가능한 문제 정의로 바꿉니다.

**준비물:** 앞 단계의 기회 매트릭스

**실행:** [`prompts/analyze/problem-framing.md`](../prompts/analyze/problem-framing.md)

**좋은 결과 기준:**
- 사용자 문제와 비즈니스 문제가 분리되어 있다.
- 아직 검증되지 않은 가정이 별도 표시되어 있다.
- 다음 실험이나 리서치 질문이 나온다.

## 3. 기능 우선순위 결정

**목표:** 해야 할 일을 RICE 기준으로 정렬합니다.

**준비물:** 기능 후보 5-10개, 대략적인 영향 범위와 개발 노력

**실행:** [`prompts/decide/feature-prioritization.md`](../prompts/decide/feature-prioritization.md)

**좋은 결과 기준:**
- 점수뿐 아니라 점수의 근거가 있다.
- Confidence가 낮은 항목은 “먼저 검증”으로 분리되어 있다.
- 바로 다음 스프린트 후보가 1-3개로 좁혀진다.

## 4. AI 기능 PRD 작성

**목표:** 우선순위가 높은 기능을 AI 제품 요구사항으로 바꿉니다.

**준비물:** 기능 목표, 사용자, 데이터 소스, 실패하면 안 되는 상황

**실행:** [`prompts/create/prd-for-ai-feature.md`](../prompts/create/prd-for-ai-feature.md)

**좋은 결과 기준:**
- 성공 지표와 실패 시나리오가 같이 있다.
- 모델 품질 기준이 숫자로 표현되어 있다.
- 개인정보, 편향, 설명 가능성 리스크가 빠지지 않았다.

## 5. 경영진 전략 브리핑

**목표:** 분석과 PRD를 의사결정 문서로 바꿉니다.

**준비물:** 결정이 필요한 안건, 기대 효과, 비용, 리스크

**실행:** [`prompts/create/executive-briefing.md`](../prompts/create/executive-briefing.md)

**좋은 결과 기준:**
- 첫 문단만 읽어도 의사결정 요청이 보인다.
- 비용, 기대 효과, 리스크가 같은 단위로 비교된다.
- “승인하면 다음에 무엇을 할지”가 명확하다.

## 초급자가 피해야 할 실수

| 실수 | 대안 |
|------|------|
| `{중괄호}`를 비워둔다 | 실제 회사명, 기능명, 데이터로 바꾼다 |
| 데이터 없이 분석을 맡긴다 | 최소한 리뷰, 인터뷰, 로그, 요구사항 중 하나를 넣는다 |
| 결과를 그대로 믿는다 | 근거, 가정, 검증 질문을 다시 요구한다 |
| 한 번에 완벽한 문서를 기대한다 | Layer 1로 시작하고, 필요한 부분만 Layer 2로 깊게 간다 |
