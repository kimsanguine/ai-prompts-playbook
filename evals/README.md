# Evaluation Guide

이 폴더는 프롬프트를 “좋아 보이는 문서”가 아니라 반복 검증 가능한 자산으로 관리하기 위한 평가 골격입니다.

## 평가 단위

각 프롬프트는 최소 3개 파일로 평가합니다.

| 파일 | 역할 |
|------|------|
| `sample_input.md` | 사용자가 실제로 넣을 법한 입력 |
| `expected_output_schema.json` | 반드시 포함되어야 하는 출력 구조 |
| `rubric.md` | 사람이 1-5점으로 채점할 기준 |

현재는 1차 개편으로 핵심 5개 시나리오를 `scenarios/core.yaml`에 정의했습니다. 다음 단계에서 프롬프트별 폴더로 쪼개면 됩니다.

## 공통 채점 기준

| 기준 | 1점 | 3점 | 5점 |
|------|----|----|----|
| 입력 반영 | 입력 대부분을 무시 | 일부 입력만 반영 | 핵심 입력을 빠짐없이 반영 |
| 구조 | 산문 위주 | 표와 항목 혼합 | 의사결정에 바로 쓰는 구조 |
| 근거 | 근거 없음 | 일부 근거 있음 | 판단마다 근거와 가정 분리 |
| 실행 가능성 | 추상적 조언 | 일부 실행 항목 | 다음 행동, 담당자, 검증 방법 명확 |
| 리스크 인식 | 낙관적 결론만 제시 | 일반 리스크 제시 | 데이터, 법무, 윤리, 운영 리스크 구분 |

## 실행 절차

1. `registry/prompts.yaml`에서 평가할 `id`를 고릅니다.
2. 해당 프롬프트의 `Layer 1` 또는 `Layer 2`를 실행합니다.
3. 같은 입력으로 ChatGPT, Claude, Gemini 등 2개 이상 모델을 비교합니다.
4. `rubric.md` 기준으로 점수를 매깁니다.
5. 프롬프트 수정 후 같은 입력으로 다시 실행해 점수 변화를 기록합니다.

## 주의

모델의 숨은 사고 과정을 요구하지 마세요. 대신 다음을 요구합니다.

- 판단 기준
- 근거 요약
- 주요 가정
- 검증 질문
- 다음 행동
